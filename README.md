# 家宴点菜小程序 · 部署手册

一个自研的微信小程序（云开发版），给朋友扫码点菜用。
主人先录好菜库 → 上架今晚的菜 → 朋友扫码点单（数量 + 口味备注 + 人数）→ 主人在后厨看板看汇总，一键复制给家人备菜。

- **技术栈**：微信小程序原生 + 微信云开发（云函数 + 云数据库）
- **现金成本**：注册 0 元、认证 0 元（个人主体免认证费）、云开发最低档约 20 元/月
- **不需要的东西**：服务器、域名、ICP 备案、微信支付、公众号
- **代码位置**：`D:\ai\DeepSeek\family-dinner-miniapp`

---

## 一、为什么是云开发（而不是你那台服务器）

小程序的 `wx.request` 只能请求**已在工信部 ICP 备案**的 HTTPS 域名，微信公众平台配置服务器域名时也会校验备案。
你那台有公网 IP 的服务器如果没有备案域名，小程序根本调不通；域名备案要 1–2 周，本周末来不及。

微信云开发把数据库和云函数都放在微信自己的环境里，**不经过服务器域名白名单**，所以免备案、免运维，还能长期复用。

## 二、部署步骤（约 30 分钟，一次做完）

### 第 1 步：注册小程序，拿到 AppID

1. 打开 https://mp.weixin.qq.com → 「立即注册」→ 选「小程序」
2. 用一个**没有注册过公众号/小程序**的邮箱注册并激活
3. 主体类型选「个人」，用身份证 + 微信扫码做人脸核身
4. 登录后台 → 「开发」→「开发管理」→「开发设置」→ 复制 **AppID(小程序ID)**

> 个人主体小程序**不需要** 300 元/年的认证费，也不需要选服务类目——体验版不走审核。

### 第 2 步：装微信开发者工具

下载「稳定版 Windows 64」：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
安装后用**小程序管理员**的微信扫码登录。

### 第 3 步：导入项目

1. 打开开发者工具 → 「+」→「导入项目」
2. **目录**选：`D:\ai\DeepSeek\family-dinner-miniapp`
3. **AppID**：已经预填在 `project.config.json` 里（`wxce5fca623936edf9`），工具会自己读出来；如果显示为空或报 AppID 错误，手动粘贴一次即可
4. 后端服务选「微信云开发」→ 点「导入」

导入后应该能看到左侧 `miniprogram` 目录和带云朵图标的 `cloudfunctions/api`。

### 第 4 步：开通云开发

1. 点工具栏的「云开发」→ 按引导开通 → 新建环境，名字随意（如 `family-dinner`）
2. 记下**环境 ID**（形如 `family-dinner-8gxxxxx`，在云开发控制台左上角环境名旁）
3. 如果你有**多个**云环境，把环境 ID 填进 `miniprogram/config.js` 的 `envId`；只有一个环境就留空

> 云开发现在是按量/包月付费（最低档约 20 元/月，以控制台实际报价为准）。家宴结束后可以在控制台停用/退订，不留后患。
>
> **只有一个云环境时，`miniprogram/config.js` 的 `envId` 留空即可**（会自动使用默认环境）。
> 如果你建了多个环境，或者运行时看到报错里提到 `env`，就把环境 ID 填进 `config.js` 的 `envId`。

### 第 5 步：部署云函数

1. 在左侧文件树右键 `cloudfunctions/api` → 「上传并部署：云端安装依赖（不上传 node_modules）」
2. 等右下角提示上传成功（第一次约 1 分钟）
3. **建议**：云开发控制台 → 云函数 → `api` → 配置 → 把**超时时间改成 20 秒**，保存

> 只有这一个云函数。为了减少出错点，所有接口都用 `action` 路由写在同一个函数里，不需要逐个部署。

### 第 6 步：初始化家宴

1. 点工具栏「编译」，模拟器里会出现「家宴还没开通」
2. 切到「我的点单」页 → 点「我是主人，一键开通」→ 你成为管理员，并生成 4 位**主人口令**
3. 进入「家宴设置与菜库」：
   - 填家宴标题、主人称呼、地址、给朋友的一句话
   - 设**点单截止时间**（比如周六 10:00），保存
   - 点「导入内置菜库」→ 66 道菜入库（**默认全部下架**，接着要勾选今晚的菜）
   - 默认已上架 14 道经典家宴菜，**按今晚实际菜单逐道勾选**（10 人桌一般 12～14 道）
   - 想限量的菜填个数字，比如「红烧狮子头 限 3 份」

### 第 7 步：发布体验版，拿到二维码

1. 开发者工具右上角「上传」→ 版本号填 `1.0.0`，备注随便 → 确定
2. 打开 https://mp.weixin.qq.com → 「管理」→「版本管理」→ 找到刚上传的**开发版本**
3. 点「选为体验版本」→ 生成**体验版二维码**（长期有效，可以截图）

### 第 8 步：把朋友拉进来

1. 后台「管理」→「成员管理」→「体验成员」→「添加成员」→ 搜朋友微信号添加
   - 上限 **60 人**，家宴远远够用
2. 把体验版二维码发到家庭群，或直接在小程序里点「···」→「发送给朋友」发分享卡片
3. 朋友扫码 → 自动进入点菜页 → 加菜、写备注、填昵称和人数 → 提交

> ⚠️ 关键点：**朋友必须是体验成员**才能打开体验版，否则会提示没有权限。所以先加成员，再发码。

## 四、功能清单

### 朋友端（不需要登录，扫码即用）
- 扫码/分享卡片进入，看到本次上架的菜（emoji + 菜名 + 描述 + 口味标签）
- 加减数量、给每道菜写口味备注（少辣 / 不要香菜 / 多放醋）
- 分类标签左右滑动快速找菜
- 提交时填昵称、到场人数、预计到达时间、整体备注（忌口）
- 提交后可随时改单（重新提交即覆盖），也可一键撤销
- **「大家都在点什么」（点菜页展开可见）**：朋友之间互相可见——每道菜共几份、都有谁点了，以及每个人带几个人、点了什么。展开时每 30 秒自动刷新；接口刻意不返回主人口令、订单 id、openid 等内部字段
- 菜品限量时会在提交时校验，被点完会提示「只剩 N 份」
- 截止时间到了自动锁单，只能看不能改

### 主人端（后厨看板）
- 到场人数、已下单人数、总份数、菜品种类四个数字
- **菜品汇总**：每道菜共几份、都有谁点了、每个人的口味备注
- **按人明细**：谁带几个人几点到、点了什么、有什么忌口
- **一键复制**：整份汇总变成纯文本，粘到家庭群或发给帮忙备菜的家人
- **下单期间每 2 秒自动刷新**（朋友那头点一下，你这里几乎立刻能看到）；离开页面自动停止，**截止后会降频到 15 秒**——那时谁也改不了单，没必要烧云函数调用次数。也可以下拉刷新
- **调整点单（三种操作）**：
  - 「菜品汇总」里每道菜右侧「**不做**」→ 从**所有人**的订单里去掉它，并自动下架（免得又被点回来）
  - 「按人明细」里每项右侧的「**×N**」→ 点它把份数改成**精确值**（朋友误点 8 份，填 2 就完事；填 0 等于去掉）
  - 「按人明细」里每项右侧「**−**」减一份、「**✕**」整条去掉
  - 改完如果那一单空了，整单删除（不留 0 道的空单把"到场人数"算多）；被改动的朋友打开「我的点单」会看到「主人去掉了：XXX」或「主人把 XXX 改成了 ×2」，他重新提交后提示自动消失

### 主人端（设置与菜库）
- 改标题 / 主人称呼 / 地址 / 提示语 / 点单截止时间（开关式）/ 每单最多点几道
- 66 道菜谱一键导入（只补新增，不覆盖你改过的）。要改菜谱就编辑 `miniprogram/data/dishes.seed.js`，然后 `node tools/make-import.js` 会校验并生成控制台导入文件
- 整组上架/下架、全部上架/下架、逐道开关
- 逐道设置限量份数、删除菜品、临时加菜
- 显示主人口令（配偶输一次也能成为主人，一起看汇总）

## 六、数据模型（云数据库）

| 集合 | 说明 | 主要字段 |
|---|---|---|
| `dishes` | 菜库 | `name` `category` `desc` `emoji` `limit`（null=不限）`tags[]` `sort` `available` |
| `orders` | 点单（每人一单） | `_openid` `nick` `partySize` `arriveAt` `note` `items[{dishId,name,emoji,qty,note}]` `totalQty` `createdAt` `updatedAt` |
| `config` | 家宴配置（单文档 `party`） | `title` `host` `address` `notice` `deadlineTs` `maxDishesPerOrder` `hostCode` `admins[]` |

设计上的两个要点：

1. **所有读写都走云函数**，云开发控制台的集合权限不用动（保持默认即可），也不会出现「客户端能改别人的单」这种越权问题。
2. 集合和初始配置由云函数自动创建（`init` 时 `createCollection`），所以你**不需要在控制台手工建集合**。

## 七、常见问题

**Q：报错 `Cannot read properties of null (reading 'admins')`**
旧版本云函数的问题（`saveConfig` 错误地依赖了 `doc().update()` 在文档不存在时抛异常）。**重新上传部署一次云函数即可**，当前代码已修好并加了回归测试。

**Q：输入框里的文字掉到框下面一半，点一下才正常**
小程序 `<input>` 是原生组件，**垂直方向的 padding 会让文字渲染错位**。当前代码已改成「显式 `height` + 只保留水平 padding」。如果你自己改了样式，注意不要在 input 上加 `padding-top/bottom`——`node tools/check.js` 会拦住这种写法。

**Q：开通成功了，但找不到主人口令 / 找不到导入菜库的入口**
主人口令和「家宴设置与菜库」都在**「我的点单」标签页**的「主人控制台」卡片里。当前版本在开通成功时会**直接弹窗显示口令**，点菜页顶部也有「家宴设置与菜库 ›」入口。

**Q：提示基础库版本过低 / 云能力不可用**
开发者工具 →「详情」→「本地设置」→「调试基础库」选 **2.2.3 以上**（推荐直接选最新稳定版）。`project.config.json` 里预置的是 `3.5.5`，如果你的工具里没有这个版本，工具会自动回退并提示，手动选一个最新版即可。

**Q：编译后提示「云函数 api 还没部署」**
按第 5 步上传部署云函数。如果右键没有「上传并部署」，先点工具栏「云开发」完成授权。

**Q：导入菜库报超时**
云函数默认超时是 3 秒，去控制台把 `api` 的超时时间改成 20 秒（见第 5 步第 3 点）。代码里已经做了并发写入，正常 1～2 秒能完成。

**Q：朋友扫码提示没有权限**
说明他不在体验成员名单里。后台「成员管理 → 体验成员」把他加上，再让他重新扫码。

**Q：能用开发版的预览二维码吗**
不建议。开发版预览二维码有效期只有几十分钟，第二天就失效。体验版二维码是长期有效的。

**Q：上传时提示要先完善基本信息**
按提示填小程序名称、头像、简介即可。类目可以先不填——体验版不走审核，不影响使用。

**Q：以后还想用怎么办**
这套东西是通用的：下次家宴只要在「家宴设置」里改标题和截止时间、重新勾选上架菜品，新朋友加为体验成员就行。菜库会一直留着。

**Q：数据在哪里**
微信开发者工具 →「云开发」→ 数据库，能看到 `dishes` / `orders` / `config` 三个集合的原始数据，也可以直接导出。

## 八、自检与已验证的行为

代码在交付前跑过两套离线测试，**不需要微信开发者工具就能跑**：

```powershell
cd D:\ai\DeepSeek\family-dinner-miniapp

node tools/check.js                 # 静态检查
node tools/test/integration.js      # 端到端集成测试
```

| 脚本 | 覆盖内容 | 当前状态 |
|---|---|---|
| `tools/check.js` | JS 语法、JSON 合法性、页面文件齐全、WXML 标签平衡、前后端接口名一致性、菜库种子格式、WXML/WXSS class 一致性、**wx:for 必须带 wx:key**、input 垂直对齐防护 | **全部通过** |
| `tools/test/integration.js` | 用本地 mock 的云开发环境真跑云函数，走完整业务流程；再加载 4 个页面并验证前端纯逻辑；含 SDK 行为差异的兼容性回归 | **全部通过** |

> 判定标准看脚本末尾那行「通过 N 项，失败 0 项」——**这行是唯一可信的计数**，会随检查项增加而变化（写作时为静态 85 项、集成 199 项）。

集成测试真正验证过的行为（这些不是"看起来对"，是跑出来的）：

- 全新环境下主人点「一键开通」直接成为管理员，并自动生成 4 位主人口令
- 朋友进来的身份是客人，**看不到主人口令**，也调不动任何管理接口
- 导入 66 道菜 → 菜库默认全部下架（朋友端看不到）；朋友端只拿到已上架的菜，重复导入不会产生重复数据
- 主人端改份数：3 份改成 1 份后朋友端立刻看到新份数与"主人把 X 改成了 ×1"的说明；改到 0 份等于去掉且空单被删；份数被夹在 0–99；**漏传份数会被拒绝**（否则漏参数会被当成"减成 0 份"误删）
- 主人端去掉菜品：只影响指定那一单 / 影响所有单（并从所有单去掉时自动下架该菜）；空单整单删除；朋友重新提交后"主人调整过"的说明自动清掉
- 朋友端的「大家都在点什么」不需要主人权限；接口不返回主人口令 / 订单 id / openid，且与主人看板共用同一份聚合逻辑（不会出现两边数字不一致）
- 限量规则：手工水饺限 4 份，老王点 2 份后，小李点 3 份被拒并提示「只剩 2 份了」
- 重复提交是**覆盖**自己那一单，不会在汇总里变成两个人
- 已截止、已下架的菜都会被服务端拦下；截止后仍能查看自己的单
- 删除某道菜后，历史汇总里仍能看到它的菜名和份数（不会丢数据）
- 超长昵称/人数/备注会被裁剪，极端输入不会写坏数据
- 看板复制出来的文本格式正确（菜品清单 + 每道菜的口味备注 + 按人明细 + 忌口）
- 购物车合计按整个购物车计算，切换分类不会让底部「已点 N 道」错误归零
- 看板自动刷新定时器：重复启动不会泄漏出第二个定时器，离开页面（onHide/onUnload）一定会被清掉
- **云开发 SDK 两种行为下初始化都不崩**：`update` 在文档不存在时「抛错」和「静默返回 `stats.updated = 0`」都测了（线上第一次初始化崩溃就是栽在后者）
- 半成品配置（有文档但一个管理员都没有）能被第一个到达的人认领，不会出现「谁也进不去」
- 样式防护：WXML 里用到的 class 必须在 wxss 里有定义；用在 `<input>` 上的 class 必须有显式 `height` 且**不能有垂直 padding**（原生组件垂直 padding 会让文字掉到框外）；每个 `wx:for` 都必须带 `wx:key`
- 看板按人明细的渲染 key 是**下标派生的唯一值**，不是昵称——家宴里两个人把昵称写一样不会导致列表渲染错乱
- 点菜页的截止状态每 30 秒本地重算一次（不发网络请求），并且**点「提交点单」时会用"现在"再判一次**，不会出现"填完整张单子才被拒绝"
